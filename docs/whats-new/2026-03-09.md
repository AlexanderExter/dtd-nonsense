**Before (broken):**

## Resolution Log

### Breaking Change: Starlight social config

`astro.config.mjs` was updated to use the new array syntax. One-line fix.

### New Vulnerability: svgo 4.0.0 (GHSA-xpqw-6gx7-v673)

`astro@5.18.0` ships an indirect dependency on `svgo@4.0.0` which has a DoS vulnerability via DOCTYPE entity expansion (Billion Laughs). `svgo@4.0.1` contains the patch.

**Resolution:** Added a flat `overrides` entry: `"svgo": "^4.0.1"`.

Remove this override when `astro` ships with `svgo@4.0.1+` natively.

### Zod v4 Build Failure

Zod v4 was installed and passed `npm run check` (tests, lint, validation). However, `npm run build` failed with:

```
Cannot read properties of undefined (reading '_zod')
  at inst._zod.parse (zod/v4/core/schemas.js:1398:46)
```

**Root cause:** `astro@5.18.0` depends on `zod@^3.25.76` and `zod-to-json-schema@^3.25.1`. The latter declares `peerDependencies: { "zod": "^3.25 || ^4" }`, causing npm to deduplicate it to the project's top-level `zod@4.3.6`. During Astro's static generation of the 404 page, the content layer creates Zod v3 schema objects and passes them through the Zod v4 parse engine — which expects a different internal object structure. The result is a `undefined._zod` crash.

**Resolution:** Reverted to `zod@^3.25.76`. No code changes needed.

**Blocker track:** This is a `zod-to-json-schema` ecosystem coordination issue. It will be resolved when Astro upgrades to `zod@^4` natively (likely Astro 6.0). At that point, the project's Zod usage requires zero code changes.

### Pre-existing baseline: CRLF line endings

`core.autocrlf=true` (Windows default) caused all tracked files to be checked out with CRLF, which Biome's formatter rejected as errors. This meant `npm run check` was failing before any upgrades could be evaluated.

**Resolution:** Added `.gitattributes` with `* text=auto eol=lf` to force LF checkout on all platforms. Ran `npm run lint:fix` to normalize 14 already-checked-out files. This is a permanent fix — future checkouts on any OS will get LF.
